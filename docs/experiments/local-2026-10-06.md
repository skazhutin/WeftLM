# Local attention measurements — 2026-10-06

MacBook Pro, Apple M1 Pro, 16 GB; MLX 0.32.3, Python 3.12.13.
Synthetic single-layer decode: batch 1, query count 1, Hq=32, Hkv=8, D=128, FP16, seed 0.
10 warmups and 50 measurements per configuration; block size 4096.
Source revision: `944497b234efc5cc0dc8acd956261405b3357723`.

| Tokens | Optimized MLX median / p95 (ms) | Local blocked median / p95 (ms) | Blocked / optimized median |
|---|---|---|---|
| 4096 | 0.684 / 0.767 | 2.480 / 3.741 | 3.62x |
| 16384 | 1.023 / 2.038 | 5.249 / 7.457 | 5.13x |
| 65536 | 2.300 / 2.863 | 17.659 / 19.242 | 7.68x |
| 131072 | 5.405 / 7.787 | 35.020 / 39.814 | 6.48x |
| 262144 | 9.581 / 14.243 | 73.622 / 100.245 | 7.68x |

All ten configurations passed the independent numerical check. Raw timings,
per-configuration numerical error, MLX peak memory, lifetime process RSS and
swap snapshots are in [the result artifacts](../../results/local-m1-pro-2026-10-06).

The current high-level blocked implementation is slower than optimized MLX
on every tested length. This identifies local computation as a likely obstacle
for the initial CP path. Component profiling is needed before attributing the
gap to casts, kernel dispatch or block synchronization.

System swap was already about 3.2 GB before the first case and grew during the
campaign, reaching about 7.0 GB. Full-reference verification happens outside
the timer but can increase memory pressure for subsequent cases. These results
are preliminary diagnostics under memory pressure, not a clean capacity or
performance demonstration. A controlled campaign must repeat them before a
practical speed claim.

This is one sequential campaign on one Mac. The p95 variation is retained in
raw data. It does not measure distributed CP, establish a network bottleneck,
or prove whole-model speed/capacity. Two-node comparisons are still pending.

## Reproduce

```sh
uv run --locked python -m weftlm bench --mode single --output results/new-single
uv run --locked python -m weftlm bench --mode local-context --output results/new-blocked
```

Use new output paths; existing measurements are never overwritten.
